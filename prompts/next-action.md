Use this optional tool only for an explicitly selected adaptive review. The fixed initial scan and one reviewer batch remain unchanged. This tool records missing facts and recommends work; it does not execute tools, authorize commands, create reviewers or establish a finding's truth.

1. Call `status` with the prepared sessionId/runId to get the current recorded `contextId`.
2. Call `observe` with a frozen `{total,collect,search,family}` recommendation budget on the first call. An event has a unique `id`, that contextId, a named `{criterionId,scope,question,material}` question, and a source `{kind,sha256,path?}`. The criterion ID must link to a requirement/criterion in this run's map. Scope is a repository-relative path. Do not relabel an old result with a newer contextId.
3. For scan/collect/search, save the actual `pack.json` or CLI `--json` result beneath this run's artifact directory with a path beginning `<runId>.`, and supply its byte hash. Native display text is not structured input. Do not parse frontier strings. For execution, supply an indexed receipt hash without a path. Submit one coarse result per named check or completed family, not one event per generated trial.
4. Call `select` with candidate actions linked to returned fact IDs: `{kind:'collect',target:'path:line'}`, `{kind:'search',query,path}`, or `{kind:'family',familyId}`. The host filters family availability; the execution tool still owns all grants and budgets. Run a returned action only within existing authorization. Every selection consumes its frozen recommendation budget.
5. Submit its result with the returned `actionKey` and original contextId. `wait-unknown` means the previous recommendation is still unsettled: never rerun it or refresh the budget. A missing result remains pending. `stop-unknown` leaves the named facts unresolved; it is not a passing review.

The tool owns `<runId>.adaptive.json`. Do not edit that journal. Read it for full evidence references and include material gaps in final reconciliation. Freshness uses recorded preflight, requirement and evidence-context identities, not a live filesystem validation. Setup errors, partial search, omitted edges and static dispatch remain unknown. A successful retrieval or experiment still needs reviewer interpretation.
